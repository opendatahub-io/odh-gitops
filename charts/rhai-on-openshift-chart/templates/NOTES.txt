=== AI Grid Usage-Log Hub ===

No object this release renders contains the writer's token: a token is not declarative, so it
is minted imperatively and handed to spokes. The store needs two imperative steps of its own
first.

{{- if $o11yHub.lokiStack.enabled }}
1. The store's CRs are skipped until their operators' CRDs exist, so a first install creates
   the Loki operator and the ingest identities but not the LokiStack itself. Wait for the
   CRDs to be created and Established, then run the same helm upgrade --install command again:
     oc wait --for=create --timeout=10m crd/lokistacks.loki.grafana.com
     oc wait --for=condition=Established --timeout=10m crd/lokistacks.loki.grafana.com
{{- if $o11yHub.objectStorage.obc.create }}
     oc wait --for=create --timeout=10m crd/objectbucketclaims.objectbucket.io
     oc wait --for=condition=Established --timeout=10m crd/objectbucketclaims.objectbucket.io
{{- end }}
   oc get lokistack {{ $o11yHub.lokiStack.name }} -n {{ $o11yHub.namespace }} tells you whether this step is still pending.
{{- if $o11yHub.objectStorage.obc.create }}

2. The ObjectBucketClaim's credentials are NOT in the storage Secret: ODF publishes them
   under key names the Loki operator does not read, and nothing translates them. The
   LokiStack stays not Ready until you run this once the claim is Bound:
     NS={{ $o11yHub.namespace }}
     OBC={{ $o11yHub.objectStorage.obc.name | default (printf "%s-bucket" $o11yHub.lokiStack.name) }}
     oc wait --for=jsonpath='{.status.phase}'=Bound obc/$OBC -n "$NS" --timeout=10m
     (
       set -euo pipefail
       STORAGE_CREDENTIAL_DIR=$(mktemp -d)
       trap 'rm -rf -- "$STORAGE_CREDENTIAL_DIR"' EXIT
       oc get cm "$OBC" -n "$NS" -o jsonpath='{.data.BUCKET_NAME}' > "$STORAGE_CREDENTIAL_DIR/bucketnames"
       printf '%s' 'https://s3.openshift-storage.svc:443' > "$STORAGE_CREDENTIAL_DIR/endpoint"
       oc get secret "$OBC" -n "$NS" -o jsonpath='{.data.AWS_ACCESS_KEY_ID}' | base64 -d > "$STORAGE_CREDENTIAL_DIR/access_key_id"
       oc get secret "$OBC" -n "$NS" -o jsonpath='{.data.AWS_SECRET_ACCESS_KEY}' | base64 -d > "$STORAGE_CREDENTIAL_DIR/access_key_secret"
       oc create secret generic {{ $o11yHub.objectStorage.secretName | default (printf "%s-object-storage" $o11yHub.lokiStack.name) }} -n "$NS" \
         --from-file=bucketnames="$STORAGE_CREDENTIAL_DIR/bucketnames" \
         --from-file=endpoint="$STORAGE_CREDENTIAL_DIR/endpoint" \
         --from-file=access_key_id="$STORAGE_CREDENTIAL_DIR/access_key_id" \
         --from-file=access_key_secret="$STORAGE_CREDENTIAL_DIR/access_key_secret" \
         --dry-run=client -o yaml | oc apply -f -
     )
{{- end }}

3. Wait for the stack, then read the endpoint spokes write to:
   oc wait --for=condition=Ready lokistack/{{ $o11yHub.lokiStack.name }} -n {{ $o11yHub.namespace }} --timeout=15m
   oc get route {{ $o11yHub.lokiStack.name }} -n {{ $o11yHub.namespace }} -o jsonpath='{.spec.host}{"\n"}'

   oc create token {{ $o11yHub.ingest.writer.serviceAccountName | default (printf "%s-writer" $o11yHub.lokiStack.name) }} \
     -n {{ $o11yHub.namespace }} --duration=8760h > "$TOKEN_FILE"
{{- else }}

4. The writer identity is managed outside this release.
   Set TOKEN_FILE to a private file containing its writer token.
{{- end }}
{{- else }}
lokiStack.enabled is false, so this release renders no store and no writer identity. The
token below comes from wherever the LokiStack spokes write to actually lives.
Set TOKEN_FILE to a private file containing that store's writer token.
{{- end }}

5. Give it to spokes one of two ways, not both:
{{- if and $o11yHub.spokePolicy.enabled $o11yHub.spokePolicy.deliverCredential }}
   ACM, which this release has enabled: put it where the policy reads it, and every
   selected spoke receives it with no further per-spoke step.
     oc create secret generic {{ $o11yHub.spokePolicy.credentialSecretName }} -n {{ $o11yHub.spokePolicy.namespace }} \
       --from-file=token="$TOKEN_FILE"
   Then label each spoke's ManagedCluster so the Placement selects it.
{{- else if $o11yHub.spokePolicy.enabled }}
   ACM delivers configuration only: spokePolicy.deliverCredential is false. Supply the
   credential through the mechanism that owns it on each spoke; this policy reads no hub
   credential Secret and does not deliver one.
{{- else }}
   ACM: set ai-grid-o11y-hub.spokePolicy.enabled and
   ai-grid-o11y-hub.spokePolicy.deliverCredential, then hold the token in a Secret the
   policy reads. It delivers to every selected spoke.
{{- end }}
   Directly: enable credential delivery on the ai-grid-o11y-spoke chart on the spoke
   cluster and pass the file to it, with
   --set ai-grid-o11y-spoke.enabled=true
   --set ai-grid-o11y-spoke.credential.enabled=true
   --set-file ai-grid-o11y-spoke.credential.token="$TOKEN_FILE"

   The first flag is not optional: the subchart is gated by condition: in Chart.yaml, so

   For a spoke outside ACM, also set ai-grid-o11y-spoke.metrics.enabled=false, or use
   docs/examples/values-ai-grid-o11y-spoke.yaml for the complete configuration.

   Delete the private token file afterwards: rm -- "$TOKEN_FILE"
